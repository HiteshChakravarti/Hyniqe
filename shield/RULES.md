# Hyniqe Shield detection rules

Rules version 0.1.0. Each rule is mapped to the [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/).

This file is generated by `scripts/build_docs.py`; edit `hyniqe_shield/rules.json` instead.

## OWASP categories

- **ASI01** Agent Goal Hijack
- **ASI02** Tool Misuse and Exploitation
- **ASI03** Identity and Privilege Abuse
- **ASI04** Agentic Supply Chain Vulnerabilities
- **ASI05** Unexpected Code Execution
- **ASI06** Memory and Context Poisoning
- **ASI07** Insecure Inter-Agent Communication
- **ASI08** Cascading Failures
- **ASI09** Human-Agent Trust Exploitation
- **ASI10** Rogue Agents

## What each rule means

### HS-INJ-001 Tries to override the AI's instructions

Text that tells the AI to ignore its earlier instructions is the classic prompt-injection pattern. A legitimate add-on has no reason to do this.

**Fix:** Do not install this. If you wrote it, remove the sentence.

### HS-INJ-002 Tells the AI to hide things from you

Instructions to keep the user in the dark are a strong sign that the add-on wants the AI to do something you would not approve.

**Fix:** Treat as malicious unless you can see a clear, harmless reason.

### HS-INJ-003 Fake priority or system tags

Tags like <IMPORTANT> or <SYSTEM> inside a tool description are a known trick to make injected text look authoritative to the AI.

**Fix:** Read the text inside the tag. If it gives the AI orders unrelated to the tool's job, do not install.

### HS-INJ-004 Asks the AI to act silently or without consent

Actions taken silently or without your consent remove you from the loop - exactly what an attacker wants.

**Fix:** Require confirmation for any action this add-on takes.

### HS-INJ-005 Tries to change the AI's identity or safety mode

Jailbreak-style text tries to switch off the AI's safeguards.

**Fix:** Do not install.

### HS-INJ-006 Gives orders about other tools (tool shadowing)

A tool that tells the AI how to use *other* tools can hijack them - for example silently changing who an email is sent to.

**Fix:** A tool's description should only describe itself. Review carefully.

### HS-INJ-007 Claims to be an official instruction

Fake authority is used to pressure the AI (or you) into trusting injected instructions.

**Fix:** Real platform instructions never arrive inside a third-party add-on.

### HS-EXF-001 Sends data to a known data-collection service

These services are commonly used to receive stolen data. Legitimate add-ons rarely send your data to them.

**Fix:** Find out exactly what is sent there. If it is your data, do not install.

### HS-EXF-002 Instructs sending your data somewhere

Natural-language instructions to move your files, keys or messages to an outside address are how agent data theft usually works.

**Fix:** Check the destination. Never let an add-on send private data to an address you don't control.

### HS-EXF-003 Uploads data with curl/wget

Command-line uploads can quietly push local data to a server.

**Fix:** Check what file or data is being uploaded and where to.

### HS-EXF-004 Encodes data before sending it

Encoding data right before a network call is a common way to hide what is being sent.

**Fix:** Review the code path; there should be a clear, harmless reason.

### HS-SENS-001 Accesses passwords, keys or private files

These locations hold SSH keys, cloud credentials, passwords, browser logins or crypto wallets. An add-on reading them can take over your accounts.

**Fix:** Only allow if the add-on's purpose genuinely requires it, and never combined with network access.

### HS-SECR-001 Contains a hard-coded secret or API key

A real key is written directly into the file. Anyone who sees the file can use it, and the add-on author may be using your account or theirs in ways you can't see.

**Fix:** Remove the key, rotate it immediately, and load secrets from environment variables or a secret manager.

### HS-CMD-001 Downloads and runs a script from the internet

Piping a downloaded script straight into a shell runs whatever the server sends - today or after it changes.

**Fix:** Download, read and pin the script instead of piping it into a shell.

### HS-CMD-002 Opens a remote control connection (reverse shell)

This pattern gives a remote attacker a live command line on your computer.

**Fix:** Do not install. If found on your machine, disconnect and investigate.

### HS-CMD-003 Destructive delete command

Commands like this can wipe your home folder or whole disk.

**Fix:** Never let an agent run broad delete commands without confirmation.

### HS-CMD-004 Runs dynamic or shell code

Running shell commands or dynamically built code means the add-on can do anything your user account can do.

**Fix:** Confirm the commands are fixed and safe, not built from untrusted input.

### HS-CMD-005 Changes permissions or installs persistence

Editing startup files, scheduled tasks or SSH authorized keys lets something keep running or keep access after you stop using it.

**Fix:** An add-on should not modify system startup or access settings.

### HS-PERM-001 Turns off safety confirmations

Disabling permission prompts or sandboxes means the AI can take any action without asking you first.

**Fix:** Keep confirmations on, especially for tools that write, delete, pay or send.

### HS-MEM-001 Tries to plant long-term memory

Planting instructions in the AI's memory makes an attack survive into future conversations.

**Fix:** Review and clear the AI's saved memory after using untrusted add-ons.

### HS-NET-001 Talks to a raw IP address

Connecting to a bare IP address instead of a named service is unusual for legitimate tools and common in malware.

**Fix:** Find out who owns that server.

### HS-NET-002 Uses unencrypted http:// for a remote address

Data sent over plain http can be read or changed by anyone on the network path.

**Fix:** Use https://.

### HS-OBF-001 Large encoded blob

Long encoded strings can hide code or instructions from human reviewers.

**Fix:** Decode it and check what it contains.

### HS-UNI-001 Hidden invisible text (Unicode tag characters)

The file contains invisible characters that spell out hidden text. People can't see it, but the AI can read it - a known way to smuggle instructions past reviewers.

**Fix:** Do not install. The decoded hidden text is shown in the finding.

### HS-UNI-002 Invisible zero-width characters

Zero-width characters are invisible. They are sometimes harmless, but can be used to hide or split words so filters miss them.

**Fix:** Remove them unless you know why they are there.

### HS-UNI-003 Text-direction override characters (Trojan Source)

Bidirectional override characters make text display differently from how it is actually read by machines, hiding malicious content in plain sight.

**Fix:** Remove them; legitimate code and instructions don't need them.

### HS-COMBO-001 Reads private data AND can send data out

The same add-on both touches sensitive data and contains a way to send data out. This combination is exactly what data theft looks like.

**Fix:** Do not install unless you fully understand and trust both parts.

### HS-MCP-001 Package version not pinned

This server is downloaded fresh each time without a fixed version. If the package is later hijacked or changes behaviour, you get the new version automatically - a 'rug pull'.

**Fix:** Pin an exact version, e.g. package@1.2.3.

### HS-MCP-002 Secret written directly in the config

A token or key is stored in plain text in the config file, where other tools, backups or repos can leak it.

**Fix:** Move it to an environment variable or secret manager and rotate the key.

### HS-MCP-003 Remote server over unencrypted http

Your AI's tool calls and results travel unencrypted to a remote server.

**Fix:** Use an https:// URL.

### HS-MCP-004 Gives access to your whole disk or home folder

The server is pointed at a very broad location, so the AI can read (and maybe change) far more than the task needs.

**Fix:** Point it at only the specific project folder it needs.

### HS-MCP-005 Container runs with dangerous host access

Privileged containers, host networking or mounting the whole host filesystem remove most of the protection a container gives.

**Fix:** Drop --privileged / --network host and mount only what is needed, read-only where possible.

### HS-MCP-006 Uses mcp-remote bridge

mcp-remote bridges to a remote server. Older versions had a serious command-injection flaw (CVE-2025-6514) triggerable by a malicious server.

**Fix:** Pin to the latest mcp-remote version and only connect to servers you trust.

### HS-MCP-007 Connects to a third-party remote server

Your AI's requests and the data in them will be sent to this remote service.

**Fix:** Make sure you trust the operator and understand what data it receives.

### HS-MCP-008 Tools auto-approved without confirmation

Tools listed here run without asking you first.

**Fix:** Only auto-approve read-only, low-risk tools.

### HS-N8N-001 Workflow runs shell commands

An Execute Command node runs commands directly on the n8n server.

**Fix:** Make sure the command is fixed and never built from incoming data.

### HS-N8N-002 Code node uses system access

A Code node loads system modules (shell, filesystem) or reads server environment variables, which can expose secrets or run commands.

**Fix:** Review the code; remove system access unless essential.

### HS-N8N-003 Public webhook with no authentication

Anyone who finds this webhook URL can trigger the workflow.

**Fix:** Add header or basic authentication to the webhook node.

### HS-N8N-004 AI agent mixes untrusted input, private data and outbound actions

This workflow's AI agent receives outside content (emails, webhooks, web pages), can reach private data, and can send data out. Together these let an attacker steer the agent into leaking data - the 'lethal trifecta'.

**Fix:** Remove one of the three, or require human approval before outbound actions.

### HS-SKILL-001 Skill can run any shell command

The skill allows the Bash tool without restricting which commands it may run.

**Fix:** Restrict it, e.g. Bash(git status:*), to only what the skill needs.

## Scoring

Each rule adds its severity weight once per scan (critical 40, high 20, medium 8, low 2, info 0); repeats add a quarter of the weight, up to four more times. The score is capped at 100.

- **Dangerous**: any critical finding, or two or more different high-severity rules
- **Caution**: any high finding, or a score of 10 or more
- **No known risks found**: everything else. This is not a guarantee of safety.
